## Migration conflicts and reproducibility

- **Verified** — `sql/phase1/C_enforcement_DO_NOT_RUN_YET.sql` explicitly states that enforcement is not ready to apply.
- **Verified** — `sql/phase1/DUP_cleanup_DO_NOT_RUN_WITHOUT_REVIEW.sql` is destructive cleanup gated only by its filename/comments.
- **Verified** — Rollback, verification, backup, and production scripts live beside deployable SQL without tooling that distinguishes them.
- **Verified** — Connected-email schema is split into Phase 2, Phase 3, and Phase 4 files plus rollback/verification scripts.
- **Missing implementation** — No committed Outlook inbound email schema, Microsoft Graph subscription table, Outlook webhook endpoint, or Outlook delta-sync implementation exists at the audited commit.
- **Unknown** — Applied migration versions and drift between production and repository require a read-only live schema export before repairs.

## Required database recovery action

- **Verified** — The first schema repair must begin with a read-only live dump of tables, columns, constraints, indexes, functions, triggers, RLS flags, policies, storage buckets/policies, extensions, and scheduled jobs.
- **Verified** — That dump must be reconciled into ordered, idempotent migrations before altering production behavior.
- **Security risk** — Applying the loose SQL directory wholesale would risk duplicate objects, policy regressions, rollback execution, and destructive duplicate cleanup.
